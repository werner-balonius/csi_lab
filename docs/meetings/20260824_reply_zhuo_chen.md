## 一、你抓对了，而且比你说的更严重

### 1.1 包率 196.27 Hz —— 确认，我复算完全一致

我逐 trial 验证了 16 个 trial，全部落在 195.2–197.0 Hz，
汇总均值 19.6267 包/100ms —— **和你的数字一模一样**。

**顺着这条线挖出了根因，比"Doppler 脚本固定 138.1 Hz"更糟：**

`scripts/doppler_position.py` 里的 `FS = 138.1  # 实测包速率`
是**死代码，从未被调用**。真正的频率轴来自
`fs = n / duration_s`，而存在性检测的两处调用
**硬编码传入 `50.0`**——那是 metadata 里的**请求**时长，
实际采集只有 35.0 s。

```
6905 / 50.0 = 138.10 Hz   ← 伪值
6905 / 35.0 = 197.29 Hz   ← 真值
```

**"138.1 Hz 实测包速率"这个数，正是用错误时长反推出来的**，
然后被写进注释、写进四份文档。这类 bug 最难发现，
因为数字看起来是有出处的。

三条独立证据确认约 197 Hz（与你的 196.27 一致）：

1. metadata `tx_delay_us=5000` → 标称 200 Hz，实测为其 99%
2. 特征表 `time_s` 跨度 0.0–34.9 s（350 个 100 ms 分箱）
3. 逐包匹配率 98.9–99.6%，与 200 Hz 标称吻合

**影响**：频率轴偏低 30.2%，存在性检测效应量被**低估**：

| trial | 旧（错误 fs） | 修正后 |
|---|---|---|
| walk_p01 | 3.95× | **5.18×** |
| walk_p02 | 3.88× | **5.25×** |
| walk_p03 | 4.16× | **4.59×** |

位置回归路径本就用真实时长，未受污染，
L3 增量 −2.0% → **−0.5%**，负增益结论不变。

已在代码中改为逐 trial 从特征表推导真实时长，
并在输出中打印 `n / dur / fs` 供核对。

### 1.2 "幅度 FFT 不是方向 Doppler" —— 你完全正确，我已收回原论证

这条最有价值。代码取 `np.abs(...)` 后做实数 FFT，
**无符号谱在物理上就无法表达运动方向**。

我在 8-20 文档里写过一句：
> "若系统具备空间分辨能力，多普勒至少应能区分走向 Tx 与走离 Tx"

**这是循环论证**——用一个不具备方向分辨能力的实现，
去论证"系统缺乏方向分辨能力"。已在
`20260820_doppler_position.md` §5 明确收回，
并把结论收窄为"多普勒能量与位置无关"。

补充一个你可能还没意识到的两难：
要做真正的复数多普勒谱，需要相位校准；
但本平台唯一有效的校准方案（相邻子载波差分，

这在 AX210 上目前无解。

### 1.4 部分脚本用索引代替真实时间 —— 属实

`doppler_position.py` 用 `(i + W/2) / fs` 推算时刻，

## 二、三处需要修正或补充

### 2.1 带宽：20 MHz，不是 80 MHz（沿用上一版的更正）

`node2:~/csi_agent.sh:39-41` 实际是
`CHANNEL="2412 20"` + `PRESET="TX_CBW_20_HESU"`，
即 **20 MHz HE20**，242 子载波剔 8 导频 = 234。
你 V4 里 `(T,234,2,1)` 的形状是对的，
但若沿用"80 MHz"的描述会导致距离分辨率算错
（20 MHz → **7.5 m**，80 MHz → 1.9 m）。

### 2.2 Node3-Node1 偏移："跨 trial"需区分"跨重启"

你给的范围 −0.686 至 +1.434 ms（跨度 2.1 ms），数值我认可。
但结论"固定偏移不能跨 trial 复用"需要加一个前提。

我查了 16 个 trial 的 metadata 时间戳：
**全部在 2026-08-11 15:31–17:31 的连续两小时内，是同一次开机。**

这一点重要，因为我们已确认**跨重启会触发固件 RF 重新校准**
（node3 跨重启频谱变化 12.77%，而零基线仅 2.83%；
天线幅度比从 0.90 变到 1.05）。

所以同一次开机内 2.1 ms 的漂移，更可能是**时钟慢漂**，
可用线性模型描述；而**跨重启**才是真正需要逐段重估的边界。
这个区分直接影响 M3 的必要性——如果只是慢漂，
一个全局线性项就够了，不必逐 trial 估。

建议你把偏移对采集时刻作图，看是单调漂移还是随机跳变。

### 2.3 "不能据此说硬件无法定位" —— 措辞对，但证据已更新

你写这句时引用的是 commit `84344c5`，
那正是我 8-20 最后一次提交，你可能没看到当天新增的两份文档：

- `docs/experiments/20260820_paper_config_comparison.md`
- `docs/PLAN_B.md`

关键发现：**Person-in-WiFi-3D 原论文自己写了 WiFi 定位精度约 0.5 m**
（§1："the localization accuracy is only around 0.5 meters due to the
random phase shift allowed by the IEEE 802.11n/ac WiFi communication standard"）。

我们实测 X 残差 0.53–1.07 m，**恰好落在这个理论极限上**。

配置差距：

| 项目 | 论文 | 我们 |
|---|---|---|
| 链路数 (Tx×Rx) | **9** (3×3) | **2** (1×2) |
| 带宽 | 20 MHz | 20 MHz（相同） |
| 子载波 | 30 | 234（我们更多） |
| 布局数 | **16** | 1–2 |
| 训练帧数 | 约 249,600 | 约 1,500 |

**带宽相同、子载波我们还更多，差距在空间维度和数据量。**

所以更准确的表述是：
> 在本配置（2 条链路）与数据规模（1500 帧）下位置信息不足；
> 论文的成功依赖 4.5 倍链路数与 166 倍数据量。

## 三、优先级建议：M0–M3 不该排第一

这是我和你唯一的实质分歧，理由是**数量级**。

### 3.1 对齐优化的收益上限可以先算出来

- 你实测相机配对误差中位数：**7.9–8.7 ms**
- 我们实测人体走动速度中位数：**0.91 m/s**
- → 8.3 ms 对应位移 **7.6 mm**
- 而实测 X 残差下限是 **530 mm**

**比值 70 倍。**

假设标签噪声与模型误差独立，即使把对齐做到**完美**：

```
sqrt(0.530² − 0.0076²) = 0.5299 m
改善 = 0.01%
```

**用 7.6 毫米的标签误差，解释不了 530 毫米的回归残差。**

你在 §8 末尾其实已经触及这一点
（"静态 A/B/C 实验适合检查标签和硬件空间可分性，
但不能单独验证同步"）——**反过来说同样成立：
同步优化解决不了空间可分性问题。**

### 3.2 你的 lag 容忍度实验：我做了，但改了问法

你 §7 提的「额外施加 0、±33、±66、±100、±200 ms」是个好诊断，
我把它提到了前置判据的位置。**但直接按原方案做会失败**，
原因是功效不足，所以我改了问法。结果已出，见
[`20260824_lag_tolerance.md`](../experiments/20260824_lag_tolerance.md)。

**为什么原方案不可行**：我先算了 oracle 灵敏度——
即使预测器完美，施加 lag 的理论涨幅由标签自身时间自相关决定：

| lag | 标签自身 RMSE | 理论涨幅 | trial 间噪声底 |
|---|---|---|---|
| **33 ms** | 0.122 m | **2.6%** | **31.7%** |
| **66 ms** | 0.145 m | **3.7%** | 31.7% |
| 200 ms | 0.251 m | 10.7% | 31.7% |
| 500 ms | 0.509 m | 38.7% | 31.7% |

**±33/±66 ms 的效应比噪声底小一个数量级。**
照原方案做必然得到平坦曲线，而平坦曲线有两种解释——
「模型不用时间信息」或「实验没功效」——**无法区分**。

**改进**：不问「性能掉多少」，改问「最优 lag 落在哪」。
极值位置不依赖绝对涨幅，对噪声稳健。

**结果**：扫描 ±1000 ms，

| 特征 | 边缘/中心 | lag\* |
|---|---|---|
| 归一化频谱 PCA-32 | +81.0% | **−10 ms** |
| 校准相位 PCA-32 | +65.4% | **−10 ms** |

零对照（打乱 CSI 特征）后曲线平坦（涨幅 −3.9% / +0.4%），
排除了「极值来自标签自相关」的可能。

**lag\* = −10 ms，小于 1/3 个相机帧**，
与你实测的配对误差中位数 7.9–8.7 ms 量级一致。
说明 **M1 已把对齐做到帧量化极限**。

M2 能消除的正是帧量化误差，由 oracle 曲线其收益上限约 **2.6%**，
而 trial 间离散度 31.7%。**这是我建议暂缓 M0–M3 的定量依据。**

> 附带收获：这条曲线独立验证了标签可信。
> 若深度标签有系统错误或时间戳错位，极值不会落在 0。
> 两种特征都指向 −10 ms，说明 `depth_to_label.py` 的坐标提取、
> `depth_frame_median` 映射、CSI↔相机时基三者都正确。

### 3.3 建议的顺序

| 顺序 | 任务 | 成本 | 判定作用 |

| 1 | 空间分辨能力判据实验 | 半天采集 | 决定整个课题路线 |

## 五、三条方法学提醒（我们踩过的坑）

既然你要做统计验证，这三条建议直接写进你的规程：

1. **置换检验在 CSI 上失效。**
   随机置换会破坏时间自相关，导致**空场数据也 p=0.0000**。
   循环块移位对单调漂移同样失效。
   正确做法：**用空场数据跑完全相同的分析程序作零分布。**

2. **必须有不含 CSI 的对照组。**
   我们三条 walk trial 的走动周期是 8.15/7.85/8.10 s，
   几乎相同——**仅用时间正弦基（不含任何 CSI）就能达到 21.5% 改善**。
   任何"CSI 能预测 Y"的结论都必须报告 CSI 的**增量贡献**。

3. **`duration_s` 在 metadata 里是请求参数，不是实际时长。**
   这正是 138.1 Hz 的来源。任何采样率推导都要用
   真实时戳或特征表跨度。

补充第四条（今天现场得到的）：

4. **用 RSSI 交叉验证几何。**
   今天干跑时 node3 比 node1 强 8 dB。若 node3 真在设计位置
   （链路外 3 m，距 Tx 3.35 m），按自由空间路径损耗应比 node1
   **弱** 0.97 dB——与实测矛盾。据此发现它实际在链路外 1 m
   （距 Tx 1.80 m，应强 4.4 dB，方向一致）。
   **布局错误在采集前就被发现，没有浪费 21 条 trial。**
   建议每次布局变更后都做一次这样的自洽性检查。

## 六、今天的判据实验（供你参考设计）

设计文档已更新并推送：
[`docs/experiments/20260821_spatial_resolvability_design.md`](../experiments/20260821_spatial_resolvability_design.md)

其中有两点可能对你的 §8 实验设计有用：

**1. 链路长度有物理下限。**
三点等分链路时，位置间距 = 链路长 / 4，
而中点第一菲涅尔区直径 = 2·√(λ·D/4)，两者增长速率不同：

| 链路长 | 位置间距 | 菲涅尔直径 | 判定 |
|---|---|---|---|
| 1.0 m | 0.25 m | 0.35 m | 重叠 ✗ |
| 2.0 m | 0.50 m | 0.50 m | 临界 |
| **3.0 m** | **0.75 m** | **0.61 m** | 可分 ✓ |

**还有一条独立约束**：位置间距必须大于人体躯干宽（0.40–0.50 m），
否则相邻两点上身体在物理上重合，"三个位置"实为同一位置。

今天场地原本是 1 m 等边三角，核算后发现无法执行，已重新布置为 3 m。

**2. 空间对照节点的位置也有要求。**
node3 作"链路外对照"时，必须到 A/B/C 距离近似相等：

| node3 位置 | 到 A/B/C | 相对差异 | 有效性 |
|---|---|---|---|
| 链路外 1 m | 1.25/1.00/1.25 m | 21.4% | ✗ |
| 链路外 3 m | 3.09/3.00/3.09 m | 3.0% | ✓ |

否则它对 B 的响应会天然强于 A/C——**这不是空间分辨力，
是几何距离差异**，会让对照判据失去意义。

你的 §8 第 2 项（"Ganmin 采集空场和人员站在实测 A/B/C 地面点的数据"）
正好用得上这两条约束。
